1. INTRODUCCIÓN
================================================================

En el ámbito de la nutrición clínica, los profesionales gestionan
pacientes, citas y planes alimenticios con herramientas dispersas
que fragmentan la información y dificultan el seguimiento del paciente.

NutriFlow centraliza estas actividades en una plataforma web accesible
desde cualquier navegador, integrando un sistema experto de inteligencia
artificial para la generación automatizada de planes nutricionales
personalizados.

OBJETIVOS DEL PROYECTO:
- Gestionar pacientes, citas y planes alimenticios en un entorno digital único.
- Ofrecer un banco de recetas colaborativo para la comunidad.
- Generar planes nutricionales personalizados mediante un sistema experto.
- Proveer al paciente acceso a sus métricas, objetivos y plan asignado.

================================================================
2. PROBLEMÁTICA / HIPÓTESIS
================================================================

PROBLEMÁTICA:
Los nutricionistas utilizan herramientas no integradas (hojas de cálculo,
agendas físicas, aplicaciones aisladas) para gestionar su práctica clínica,
generando fragmentación de la información, pérdida de continuidad en el
seguimiento del paciente y aumento de la carga administrativa.

HIPÓTESIS:
El desarrollo de una plataforma web con arquitectura modular y un sistema
experto basado en el modelo matemático de Harris-Benedict permitirá
centralizar la gestión nutricional, reducir la carga administrativa del
nutricionista y mejorar la continuidad del seguimiento del paciente dentro
de un entorno digital estructurado.

================================================================
3. METODOLOGÍA
================================================================

Se empleó un enfoque incremental por módulos funcionales, donde cada
incremento corresponde a un subsistema completo y desplegable, validado
de forma independiente antes de la integración:

  Módulo 1: Autenticación y perfil del nutricionista
  Módulo 2: Gestión de pacientes (CRUD + foto de perfil)
  Módulo 3: Calendario de citas
  Módulo 4: Banco de recetas dinámico
  Módulo 5: Motor de recomendación nutricional (IA)

HERRAMIENTAS Y TÉCNICAS:
- Frontend:          Angular v21 + TypeScript + Angular Material
- Backend:           ASP.NET Core 8 (C#) · API REST
- Base de datos:     PostgreSQL vía Supabase · Row Level Security
- Despliegue:        Vercel (frontend) · Railway (backend)
- Control de versiones: GitHub (repositorio público)

4. DESARROLLO Y TECNOLOGÍA
================================================================

El sistema implementa un SISTEMA EXPERTO NUTRICIONAL con tres
componentes de inteligencia artificial:

— ÁRBOL DE DECISIÓN: ajuste calórico según objetivo clínico

  ¿Cuál es el objetivo nutricional?
         /            |             \
  Pérd. grasa    Mantenimiento   Gan. muscular
       |               |               |
  TDEE − 400       TDEE + 0       TDEE + 400  (kcal/día)

  ¿Distribución de proteína?
  Pérd. grasa → 2.0 g/kg · Mantenimiento → 1.6 g/kg · Gan. muscular → 2.2 g/kg

— MODELO MATEMÁTICO (Harris-Benedict / Mifflin-St Jeor, 1990)

  TMB (femenino) = 447.593 + (9.247 × w) + (3.098 × h) − (4.330 × a)
  TMB (masculino) = 88.362 + (13.397 × w) + (4.799 × h) − (5.677 × a)
  TDEE  = TMB × fa      (fa: Sedentario 1.200 → Muy activo 1.900)
  C_obj = TDEE + δ      (δ ∈ {−400, 0, +400} kcal según objetivo)
  P  = w × cP           (proteína en gramos)
  G  = (C_obj × 0.25) / 9      (grasas en gramos)
  HC = (C_obj − P×4 − G×9) / 4 (carbohidratos en gramos)

  Distribución por tiempo de comida:
    Desayuno = C_obj × 0.25
    Comida   = C_obj × 0.40
    Cena     = C_obj × 0.35

— K-NN PARA SELECCIÓN DE RECETAS (k = 5)

  Para cada tiempo de comida se ordenan las recetas por distancia
  calórica absoluta |receta.kcal − C_s|, se toman los 5 más cercanos
  y se elige aleatoriamente entre ellos, introduciendo variabilidad
  controlada que simula el criterio del nutricionista.

  Complejidad: O(n log n) donde n = tamaño del banco de recetas.

ARQUITECTURA DE TRES CAPAS:
  [Presentación]  Angular v21 · Vercel
        ↕ HTTP/REST · JSON · JWT
  [Negocio]       ASP.NET Core 8 · C# · Railway
        ↕ Supabase SDK · HTTPS
  [Persistencia]  PostgreSQL · Supabase · Row Level Security

================================================================
7. CONCLUSIONES
================================================================

- Se obtuvo una plataforma web funcional que centraliza la gestión
  nutricional bajo una arquitectura modular cliente-servidor de tres
  nodos independientes (Vercel / Railway / Supabase).

- El sistema experto demostró 100% de precisión matemática en la
  validación cuantitativa del modelo Harris-Benedict (desviación ≤ 0.01%).

- La precisión calórica promedio de las recomendaciones superó el 85%
  con un banco de 45 recetas categorizadas (desayuno / comida / cena).

- La separación en tres nodos independientes garantiza resiliencia,
  escalabilidad y dominios de fallo aislados.

- El proyecto establece una base sólida y extensible para el ámbito
  de la salud digital.

8. TRABAJO A FUTURO
================================================================

1. MODELO DE ML: entrenar con datos reales de pacientes para
   personalizar las recomendaciones más allá de reglas clínicas generales.

2. RESTRICCIONES ALIMENTICIAS: ampliar la base de conocimiento con
   recetas para alergias, intolerancias y preferencias culturales.

3. WEARABLES: integrar datos de actividad física en tiempo real para
   actualizar el factor de actividad dinámicamente.

4. SEGUIMIENTO: módulo que compare el plan asignado con el consumo
   real del paciente y genere retroalimentación automatizada al nutricionista.
